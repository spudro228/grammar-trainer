## 4. Формат контента

Один типизированный файл на главу: `src/content/ch01.ts` (структура та же, что JSON ниже, плюс типы из `src/types.ts`). Файл создан вручную из OCR-текста и сверен по картинке каждой страницы. OCR содержит ошибки (`lS` вместо `is`, `AJnyandi` вместо `Amy and I`). Автоматический парсинг не применяем.

```json
{
  "chapter": 1,
  "title": "Using Be",
  "blocks": [
    { "kind": "chart", "id": "1-1", "title": "Singular Pronouns + Be",
      "html": "<table>…</table>" },
    { "kind": "exercise", "id": "1.3", "number": 3,
      "title": "Looking at grammar", "charts": ["1-1"], "page": 2,
      "type": "fill",
      "instruction": "Write the correct pronoun: he, she, or it.",
      "image": null,
      "items": [
        { "n": 1, "text": "Mary ___", "answers": [["she"]], "example": true },
        { "n": 5, "text": "Dr. Jones ___", "answers": [["he", "she"]] }
      ]
    }
  ]
}
```

Правила:
- `text` содержит `___` на месте каждого пропуска. Число пропусков = число элементов в `answers`.
- `answers[i]` — список допустимых вариантов для пропуска `i`. Вариант «he or she» в ключе = два допустимых ответа.
- Для `choice`: поле `options: ["a. is", "b. are", "c. Ø"]` и `answers: [["b"]]`.
- Для `rewrite`: `answers: [["They are absent."]]`. Сокращённые формы добавляем как варианты: `["He isn't late.", "He's not late."]`.
- Для `info`: `items` пустой. Текст задания показываем целиком.

## 5. Проверка ответа

Нормализация перед сравнением:
1. Обрезать пробелы по краям.
2. Привести к нижнему регистру.
3. Заменить `’` на `'`.
4. Схлопнуть несколько пробелов в один.
5. Удалить все точки. Удалить `?` и `!` в конце.

Ответ верный, если нормализованная строка равна одному из вариантов `answers[i]`.
Проверка идёт по кнопке «Проверить» на уровне упражнения или по кнопке «✓» у пункта. Enter в поле ничего не делает: он нужен для японского ввода (IME). Ответы просто остаются в полях, проверка или отправка преподавателю — отдельным нажатием.

Пропуск по правилу: если верный ответ — «ничего», в контенте он записан как `''`. У полей такой части есть кнопка «Ø». Ввод `Ø`, `-` или `ничего` тоже считается этим ответом. Пустое поле — это не ответ «ничего».

## 6. Интерфейс

Главная страница (`#/`): карточки учебников из `src/books.ts` с прогрессом, кнопки Экспорт/Импорт/Очистить. Учебник открывается по адресу `#/<book>`, вкладки — `#/<book>/progress`, `#/<book>/review`. В шапке учебника ссылка «← Главная».

Макет учебника повторяет книгу:
- Левая колонка: оглавление главы. Список charts и упражнений. Иконка статуса у каждого упражнения.
- Основная колонка: контент главы в порядке книги. Chart — таблица с красной шапкой, как в книге. Упражнение — заголовок `Exercise N. Тип. (Chart X-Y)`, инструкция, список пунктов в две колонки.
- Под каждым упражнением кнопки: **Проверить**, **Показать ответы**, **Для преподавателя**, **Сбросить**. Для `info` одна кнопка **Выполнено**.
- **Для преподавателя** сохраняет упражнение с ответами ученика в оформленный HTML-файл `exercise-<id>_<дата>_<время>.html` (ответы выделены жёлтым, пустые пропуски пунктиром) и копирует текстовую версию в буфер обмена (ответы в скобках 【 】). Картинки из книги в файл не входят.
- У главы с `check: false` (японский учебник) кнопок «Проверить» и «Показать ответы» нет. Остаются «Выполнено», «Для преподавателя», «Сбросить». Вкладка «Повторить ошибки» скрыта.

Подсветка после проверки:
- Верный пропуск: зелёная рамка.
- Неверный пропуск: красная рамка. Правильный ответ показан рядом серым текстом.
- Пустой пропуск: жёлтая рамка. Не считается ошибкой и не идёт в историю. Упражнение с пустыми пропусками не получает статус `done`.

Статус упражнения:
- `new` — нет ответов.
- `partial` — есть ответы, не все верные.
- `done` — все пропуски верные или нажато «Выполнено».

## 7. Хранение данных

MVP без сервера. Данные в `localStorage` браузера. Экспорт и импорт в JSON-файл кнопками в шапке.

Таблицы (ключи localStorage):
- `attempts`: массив записей `{ ts, exerciseId, partIndex, itemN, blank, answer, correct, attemptNo, first }`. Запись создаётся при каждой проверке на каждый заполненный пропуск. `first` — первая попытка для этого пропуска.
- `progress`: словарь `exerciseId → { status, firstTryCorrect, firstTryTotal, lastTs }`.
- `drafts`: текущие значения полей. Сохраняются при вводе.

Правило статистики: в статистику темы идёт только первая попытка по каждому пропуску (`first = true`). Повторные попытки хранятся, но считаются отдельно.

## 8. Статистика и прогресс

Страница «Прогресс»:
- Таблица по charts: `chart | упражнений | выполнено | точность первой попытки %`.
- Правило «слабая тема»: точность первой попытки < 80 %. Строка выделена красным.
- Прогресс главы: `done / всего` упражнений. Полоса прогресса в шапке.
- Список ошибок: последние 50 неверных ответов. Столбцы: упражнение, пункт, мой ответ, верный ответ, дата.

Режим «Повторить ошибки»:
1. Приложение собирает все пункты с `correct = false` в первой попытке.
2. Приложение показывает их одним списком с пустыми полями.
3. Проверка и хранение работают как в обычном режиме. `attemptNo` увеличивается.

## 14. Проверка преподавателем (добавлено 2026-10-23)

Несколько заданий сразу (добавлено 2026-10-29): галочка в заголовке задания (у заданий, где есть что заполнять), внизу главы панель «Выбрано заданий: N» — «Отправить преподавателю» (онлайн, каждое задание уходит отдельной работой; отправленные снимаются с выбора), «Для преподавателя» (один файл `exercises-<первое>--<последнее>_<дата>_<время>.html` со всеми выбранными заданиями и общим набором проверки, текст всех в буфере обмена; при одном выбранном — обычный `exercise-<id>_…html`), «Выбрать все», «Снять выбор». Выбор не сохраняется между главами и перезагрузками. Проверенный общий файл ученик загружает кнопкой «Загрузить проверку» в любом из его заданий: пометки расходятся по заданиям (по `exerciseIds` в блоке review и префиксу ключа), комментарий и рукописные пометки общие для всех.

Офлайн-цикл через файлы, без сервера:

1. Ученик нажимает **Для преподавателя**. Скачивается `exercise-<id>_<дата>_<время>.html`: задание, ответы ученика (жёлтым), пустые пропуски (пунктиром) и встроенный набор проверки (`src/reviewKit.ts`). Файл самодостаточен, открывается в любом браузере, в том числе на планшете.
2. Преподаватель в файле: нажимает на ответ — ответ зачёркивается, рядом поле «исправление»; на пустой пропуск — поле для нужного ответа; пишет комментарий внизу; кнопка **Ручка** включает рисование поверх страницы (стилус с нажимом, мышь, палец; ладонь при стилусе игнорируется), есть ластик, отмена, цвет; снизу страницы запас места для рукописных заметок. **Сохранить проверку** записывает состояние в `<script id="review" type="application/json">` (отметки, комментарий, рисунок как PNG) и скачивает `exercise-<id>_<дата>_<время>-checked.html`.
3. Ученик нажимает **Загрузить проверку** в упражнении и выбирает этот файл. В приложении: значок «проверено», зачёркнутые поля, исправления зелёным, комментарий, рукописные пометки по кнопке. Проверки хранятся в `reviews` (localStorage, входят в экспорт/импорт JSON). Проверенный файл тоже можно просто открыть в браузере.

Ширина страницы выгрузки фиксирована (820 px), чтобы рисунок совпадал с текстом на любом экране.

Онлайн-режим (преподаватель видит задание сразу, ученик получает ответ без пересылки файлов) без сервера невозможен. Варианты: (а) обмен файлами через мессенджер — уже работает; (б) статический хостинг приложения + облачная база (Supabase/Firebase) с общим кодом ученика и преподавателя; (в) свой небольшой сервер. Решение отложено до выбора пользователя.

## 15. Инфраструктура и онлайн-режим (добавлено 2026-10-23)

Выбран вариант (в) из раздела 14: свой небольшой сервер. Клиент остаётся офлайн-первым: localStorage — источник истины, сервер хранит снимки и обмен с преподавателем.

- **Сервер** `server/`: Node 22, `node:http` без фреймворка, `pg`. Хранилище за интерфейсом `Store`: `PgStore` (prod) и `MemoryStore` (тесты и интеграционный тест клиента). Схема `server/src/schema.sql` применяется на старте.
- **Общие типы** `shared/api.ts`: `Review`, DTO API, guard-функции `isReview`, `isSubmissionInput` — одна проверка формы данных для файла проверки и для тела запроса.
- **Клиент**: `src/api.ts` (fetch-обёртка, адрес `VITE_API_URL`, по умолчанию `/api`), `src/online.ts` (доступность сервера, код ученика в `grammar-trainer:student`), `src/sync.ts` (push/pull состояния, отправка работы, получение проверок). Главная: раздел «Онлайн». Упражнение: кнопка «Отправить преподавателю» при наличии сервера и кода. Маршрут `#/teacher` — кабинет преподавателя.
- **Набор проверки**: сервер отдаёт файл работы с `data-review-url` в `<body>`; при его наличии «Сохранить проверку» делает POST вместо скачивания, при ошибке — скачивает файл как раньше.
- **Доступ** (роли добавлены 2026-10-23 по просьбе пользователя): таблица `users` с ролями student / teacher / admin и секретным токеном. Все запросы с `Authorization: Bearer`; ссылка на файл работы несёт токен в `?key=`. Ученик видит только своё, преподаватель — все работы и проверку, администратор — всё плюс управление пользователями и кабинеты (`#/admin`). Администратор один, токен из `ADMIN_TOKEN`. Для публичного интернета нужен HTTPS — вне MVP.
- **Docker**: `Dockerfile` (web, nginx), `server/Dockerfile` (api), `compose.yml` (db + api + web, порт 8080), `compose.dev.yml` (HMR), `compose.test.yml` (`npm run check` с Postgres). `Makefile` с короткими командами.
- **Компиляция и тесты**: строгие флаги tsc, typescript-eslint strict-type-checked, `npm run check`. Vitest: node-окружение для чистых тестов, `pool: threads`; весь набор около 2 с.

Не сделано: автоматическая синхронизация состояния (пока по кнопкам), уведомления ученику о новой проверке, HTTPS, несколько администраторов, привязка учеников к конкретному преподавателю (сейчас общий список работ).

## 16. Логирование и разбор жалоб (добавлено 2026-10-23)

Цель: по жалобе пользователя восстановить, что произошло, без его участия.

- API: pino, JSON в stdout, один объект на запрос (`requestId`, пользователь, метод, путь без секретов, статус, время), стек при 500. `x-request-id` в ответе, `requestId` в теле ошибки, Sentry/GlitchTip при `SENTRY_DSN`.
- Клиент: кольцевой журнал (`src/log.ts`, 300 событий, хвост в sessionStorage), `ErrorBoundary`, глобальные обработчики, автоотчёт при сбое, кнопка «Сообщить о проблеме». `POST /api/client-logs` принимает отчёт и без токена; хранится в `client_reports`, виден в `#/admin`.
- Инфраструктура: `compose.logs.yml` — Loki 3.7 + Alloy 1.21 + Grafana 13 (логи контейнеров, 30 дней) и GlitchTip 6.2 + Redis (ошибки). GlitchTip живёт в той же Postgres (база `glitchtip` создаётся `docker/db-init.sql` при первой инициализации тома).
- Логи контейнеров: json-file с ротацией 5×20 МБ.

Не сделано: трейсы (Tempo/Jaeger) — для одного сервиса пока не нужны; алерты.
