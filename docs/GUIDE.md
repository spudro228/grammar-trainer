# Grammar Trainer: руководство

Тренажёр по учебнику Azar & Hagen, *Basic English Grammar*, 4e. Упражнения из книги с полями для ответа, проверкой по ключу, историей ошибок и прогрессом по темам.

Спецификация: `docs/MVP.md`. Сейчас есть глава 1 «Using Be».

## Запуск

Без сервера (только localStorage, обмен с преподавателем файлами):

```bash
npm install
npm run dev      # http://localhost:5173
npm run check    # типы (tsc, оба проекта) + ESLint с проверкой типов + vitest
npm run build    # сборка в dist/, открывается как статический сайт
```

С сервером и базой (онлайн-режим: код ученика, отправка работ, кабинет преподавателя):

```bash
cp .env.example .env     # пароль базы и ADMIN_TOKEN (openssl rand -hex 24)
make up                  # docker compose up -d --build → http://localhost:8080
make logs
make down                # make clean — вместе с данными базы
```

Разработка с горячей перезагрузкой в контейнерах: `make dev` (клиент :5173, API :3000, Postgres :5432).
Без Docker: поднять Postgres любым способом и запустить `DATABASE_URL=postgres://… npm run dev:api` рядом с `npm run dev` (Vite проксирует `/api` на :3000).

Проверки в контейнере, включая тесты API на настоящем Postgres: `make test`. Локально `npm run check` (тесты на Postgres пропускаются, если нет `TEST_DATABASE_URL`).

Нужен Docker: Docker Desktop, OrbStack или `brew install docker docker-compose colima && colima start`.

## Выкладка на сервер

Нужен VPS с Docker и ssh-алиасом (например `radar`). Скрипт `scripts/deploy.sh [хост]` копирует исходники rsync-ом (без `node_modules`, `.env`), собирает образы на сервере по одному (хватает 2 ГБ памяти) и поднимает `compose.yml` + `compose.prod.yml`: Caddy на 80/443 с автоматическим сертификатом Let's Encrypt, web и api только во внутренней сети. При первом запуске на сервере создаётся `.env` со случайными `POSTGRES_PASSWORD` и `ADMIN_TOKEN` (печатается в консоль) и адресом `SITE_ADDRESS=<ip-с-дефисами>.sslip.io`; свой домен — поменять `SITE_ADDRESS` и направить DNS на сервер. Стек логов (`compose.logs.yml`) на 2 ГБ не разворачивается: логи смотреть `docker compose logs api`.

## Устройство

- `src/` — клиент (Vite + React + TS). `server/` — API (Node 22, `node:http`, `pg`), отдельный workspace. `shared/api.ts` — типы и guard-функции, общие для клиента и сервера.
- `Dockerfile` — клиент: сборка Vite → nginx (`docker/nginx.conf`, прокси `/api` → `api:3000`). `server/Dockerfile` — API. `compose.yml` — prod, `compose.dev.yml` — разработка, `compose.test.yml` — проверки с базой.
- База: `server/src/schema.sql`, применяется при старте API (идемпотентно). Таблицы `users` (роль, имя, токен), `states` (снимок localStorage ученика как jsonb), `submissions` (присланные работы: HTML с ответами, текст, проверка как jsonb, кто проверил).
- API (`server/src/app.ts`), все запросы кроме `health` и регистрации — с `Authorization: Bearer <токен>` (для ссылок в новой вкладке — `?key=`): `GET /api/me`, `POST /api/students` (регистрация ученика), `GET /api/students/:id`, `GET|PUT /api/students/:id/state`, `POST /api/students/:id/submissions`, `GET /api/students/:id/reviews`, `GET /api/submissions[?student=|?reviewer=]`, `GET /api/submissions/:id/file`, `POST /api/submissions/:id/review`, `GET|POST /api/admin/users`, `DELETE /api/admin/users/:id`, `POST /api/admin/users/:id/token`, `GET /api/health`.

## Роли и токены

- **Ученик**: регистрируется сам на главной (имя → код и токен) или получает токен от администратора. Видит только свои данные. Код (вида `k7f3-9q2x`) не секрет, его сообщают преподавателю. Токен (48 знаков) секрет, нужен для входа на другом устройстве.
- **Преподаватель**: токен выдаёт администратор. Кабинет `#/teacher`: все присланные работы, проверка в файле с сервера. Свои проверенные работы: `?reviewer=`.
- **Администратор**: один, токен из `ADMIN_TOKEN` (пересоздаётся при каждом старте API). Страница `#/admin`: создать преподавателя или ученика, выдать новый токен, удалить, открыть кабинет ученика (снимок прогресса, работы) или преподавателя (проверенные работы). Также доступен кабинет преподавателя.

Вход: раздел «Онлайн» на главной, поле «Токен». Сессия хранится в localStorage (`grammar-trainer:session`), «Выйти» её удаляет. Токен сравнивается через `timingSafeEqual`. Смена схемы с v1 (без ролей): пересоздать базу (`make clean && make up`).

## Ошибки на этапе компиляции

`tsconfig` включает `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns`, `noImplicitOverride`, `verbatimModuleSyntax`. ESLint (`eslint.config.js`) — `typescript-eslint` в режимах `strictTypeChecked` + `stylisticTypeChecked` и правила хуков React: плавающие промисы, `any`, лишние условия и небезопасный доступ ловятся до запуска. Данные извне (файл проверки, тело запроса) проходят guard-функции из `shared/api.ts`.

## Логи и отчёты о проблемах

- **API** пишет JSON-строки (pino) в stdout: на каждый запрос `requestId`, `userId`, `role`, `method`, `path`, `status`, `ms`; ошибки сервера — со стеком. `LOG_LEVEL=debug|info|warn`, в разработке `LOG_PRETTY=1` (уже в `npm run dev:api`). Ответ несёт заголовок `x-request-id`, а ошибка в JSON — `requestId`; клиент показывает его пользователю как «код» при ошибках сервера.
- **Клиент** ведёт журнал последних 300 событий (`src/log.ts`): переходы, действия (проверка, отправка, вход), запросы к API со статусом и `requestId`, ошибки (включая необработанные и ошибки рендера React через `ErrorBoundary`). Ответы ученика и токены в журнал не попадают. Кнопка **Сообщить о проблеме** на главной отправляет описание + журнал на `POST /api/client-logs` (или скачивает JSON, если сервера нет). При сбое отчёт уходит автоматически (не больше трёх за сессию). Администратор смотрит отчёты и журналы на `#/admin`, раздел «Отчёты о проблемах»; сервер дублирует их в лог уровня `warn`.
- **Метка сборки** `APP_BUILD` (в `.env`) попадает в логи API, журнал клиента и отчёты: по ней видно, какой код работал.
- **Сбор логов** (`compose.logs.yml`, `make up-logs`): Grafana Loki хранит логи всех контейнеров 30 дней, Grafana Alloy собирает их через Docker API и разбирает JSON API в поля; Grafana на `:3001` (источник данных Loki уже настроен). Пример запроса: `{service="api"} | requestId="…"` или `{service="api"} | level="error"`.
- **Ошибки со стектрейсами**: GlitchTip на `:8001` (Sentry-совместимый). После первого входа создайте организацию и проект, DSN запишите в `.env` как `SENTRY_DSN` (API) и `VITE_SENTRY_DSN` (клиент), пересоберите `make up-logs`. Без DSN всё остальное работает.

Как разбирать жалобу: взять `requestId` из сообщения пользователя или отчёт на `#/admin` → в Grafana найти запрос по `requestId` → по `userId` посмотреть соседние запросы → в GlitchTip открыть стектрейс, если это исключение.

## Тесты

`vitest`, около 2 с на всё. Чистые тесты помечены `// @vitest-environment node` и не поднимают jsdom. `server/src/app.test.ts` гоняет API через реальный `node:http` на хранилище в памяти, а при `TEST_DATABASE_URL` — ещё раз на Postgres. `src/components/Online.test.tsx` проходит весь онлайн-цикл с ролями: регистрация → отправка работы → преподаватель входит по токену и проверяет в файле с сервера → ученик получает проверку → администратор видит кабинеты и отчёты о проблемах.

- `src/types.ts` — типы контента и хранилища (`Review` берётся из `shared/api.ts`).
- `src/check.ts` — нормализация и сравнение ответов.
- `src/store.ts` — localStorage: попытки, прогресс, черновики, проверки.
- `src/api.ts`, `src/online.ts`, `src/sync.ts` — клиент API, код ученика, синхронизация.
- `src/components/` — Chart, Exercise, Progress, Review, Home, OnlinePanel, Teacher.
- `public/img/` — картинки, вырезанные из PDF. `source/` — OCR-текст для сверки.

## Учебники

- `azar` — Azar & Hagen, Basic English Grammar 4e. Глава 1. Ответы по ключу из книги.
- `minna` — みんなの日本語 初級 I 第2版. Все 25 уроков (`src/content/mnn01.ts`…`mnn25.ts`, картинки в `public/img/mnnNN/`): 本冊 (練習B, 練習C, 問題) и 標準問題集 (ответы по ключу). Адрес урока `#/minna/<N>`, вкладки `#/minna/<N>/progress`; в шапке выпадающий список уроков. Автопроверки нет (`check: false`): задания уходят преподавателю. Ответы в контенте есть (標準問題集 по ключу, 本冊 составлены по образцам и картинкам), но в интерфейсе не показываются. Повторительные разделы (復習, まとめ) не набраны. Аудиозадания (問題 1–3) — поля без проверки с номером трека CD.

Японский ввод: Enter ничего не делает, он нужен для IME. Пропуск «частица не нужна» — кнопка «×». Нормализация (`normalizeJa`) готова на случай включения автопроверки.

## Проверка преподавателем

Онлайн (нужен сервер): ученик на главной создаёт код или входит по коду, в упражнении нажимает «Отправить преподавателю». Преподаватель открывает `#/teacher`, в списке работ нажимает «Открыть»: та же страница с набором проверки, но «Сохранить проверку» отправляет результат на сервер. Ученик нажимает «Получить проверки» на главной. «Сохранить на сервер» / «Загрузить с сервера» переносят прогресс между браузерами.

Офлайн: «Для преподавателя» скачивает `exercise-<id>_<дата>_<время>.html`. Преподаватель открывает файл в браузере, зачёркивает ответы, вписывает исправления, пишет от руки (кнопка «Ручка», стилус поддерживается), нажимает «Сохранить проверку» и отправляет `exercise-<id>_<дата>_<время>-checked.html` обратно. Несколько заданий, отмеченных галочками, панель внизу главы сохраняет одним файлом; проверка из него загружается сразу во все задания. Ученик загружает его кнопкой «Загрузить проверку». Подробнее: `docs/MVP.md`, раздел 14.

## Добавить главу

1. Извлечь текст: `pdftotext -layout -f <PDF-стр> -l <PDF-стр> book.pdf`. Страница PDF = страница книги + 12.
2. Создать `src/content/chNN.ts` по образцу `ch01.ts`. Сверять каждое упражнение с изображением страницы.
3. Добавить тест по образцу `ch01.test.ts` и подключить главу в `src/books.ts` (массив `chapters` нужного учебника). Новый учебник — новая запись в `books` с уникальным префиксом идентификаторов упражнений.
4. Если пропуск по правилу остаётся пустым (например, артикль Ø), записать ответ как `''`. У полей появится кнопка «Ø».
